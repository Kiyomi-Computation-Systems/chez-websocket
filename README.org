** Status

The primitives are done (M1): SHA-1, base64 and a UTF-8 checker that takes a
text in pieces. So is the frame codec (M2): it reads a client's frames in
pieces of any size, refusing what no client may send, and builds the
server's. Each is held to its RFC's test vectors and examples. Nothing a
handler can use runs yet; the protocol (M3) is next. The plan: a handler takes
a WebSocket handshake, and its code reads each message with a call that waits,
sends messages, and closes, as RFC 6455 asks.
No compression and no client.
[[https://github.com/crossbario/autobahn-testsuite][Autobahn|Testsuite]] will hold
it to the RFC in CI. See [[file:.plans/2026-10-04-chez-websocket-project-brief.md][the project brief]],
[[file:.plans/2026-10-04-chez-websocket-design.md][the design]] and
[[file:.plans/2026-10-04-chez-websocket-milestone-plan.md][the milestone plan]].

** Building

You need Chez Scheme 10.4.1 or later, built with threads, and libuv 1.44 or
later. The one dependency, chez-http-server, is a submodule pinned at a release
tag, and it brings its own pinned dependencies. All but chez-srfi are private.

#+begin_src sh
make submodules   # clone chez-http-server v0.3.0 and the pins it carries
make test         # build chez-libuv's shim, check every pin, run the suites
make help         # every target
#+end_src
